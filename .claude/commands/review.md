이 프로젝트의 변경 사항을 리뷰하라.

먼저 다음 문서들을 읽어라:
- `/AGENTS.md`
- `/docs/` 하위 문서 전부 (ARCHITECTURE, ADR, 그리고 프로젝트가 추가한 기준 문서)
- `/.claude/skills/failure-patterns/SKILL.md`

그런 다음 변경된 파일들을 확인하고, 아래 체크리스트로 검증하라:

## 체크리스트

1. **아키텍처 준수**: ARCHITECTURE.md에 정의된 디렉토리 구조를 따르고 있는가?
2. **기술 스택 준수**: ADR에 정의된 기술 선택을 벗어나지 않았는가?
3. **테스트 존재**: 새로운 기능에 대한 테스트가 작성되어 있는가?
4. **CRITICAL 규칙**: AGENTS.md의 CRITICAL 규칙을 위반하지 않았는가?
5. **검증 통과**: `make verify`가 에러 없이 통과하는가?
6. **프로젝트 기준 문서**: 프로젝트가 `/docs/`에 추가한 기준(UI 가이드, 평가 기준 등)이 있다면 그 기준을 지키는가? 수치 기준이 있다면 이전 결과보다 나빠지지 않았는가?
7. **실패 패턴**: 변경된 코드·테스트에 failure-patterns의 패턴이 다시 나타나지 않는가? 특히 외부 서비스 응답을 `docs/CONTRACTS.md`에 없는 형태로 가정하거나 손으로 쓴 가짜 응답으로만 검증하는지(FP-C01, B-FP-020), 모델 응답에서 답의 위치를 순서로 찾는지(FP-C02), 테스트 기대값에 모델이 생성한 문장·분류 값을 굳혔는지(FP-C03), 무작위·난수·`uuid`를 고정해 간헐적 실패를 가렸는지(B-FP-011), 동시 실행 결과의 순서를 단언하는지(B-FP-012), 개수·위치·정확 일치 단언을 새로 만들었는지(B-FP-061·071), 빈 집합에 대한 `all()`로 공허하게 통과하는지(B-FP-069), 기본값이 있는 환경 변수를 한 함수로 읽는지(B-FP-030), 시간 제한 없는 대기가 있는지(B-FP-066), 0건 지표를 짝 지표 없이 판정하는지(B-FP-040), 실행 경로 코드가 평가 정답을 읽는지(B-FP-042), 완화한 단언을 되돌렸는지(B-FP-056).
8. **요청 반영**: 이번 phase 중 요청된 수정 항목이 모두 커밋에 반영됐는가? 여러 항목 요청은 항목별 반영 여부와 커밋을 대조한다.
9. **step 범위 밖 변경**: `git diff --stat`의 변경 파일이 각 step이 허용한 범위 안인가? 특히 `.claude/`, `docs/EVAL.md`의 판정 기준, `tests/fixtures/contracts/`의 응답 원본이 지시 없이 바뀌지 않았는가.
10. **외부 계약 실측 목록**: 설계 초안의 "외부 계약 실측 목록"과 "첫 live에서 터질 수 있는 것" 목록이 있고 구현(사전 점검·픽스처)이 그 목록과 대응하는가? 새로 쓴 외부 지점이 `docs/CONTRACTS.md`에 추가됐는가(B-FP-050·051).
11. **머지 후 사용자 실행**: PR 본문에 "머지 후 사용자 실행" 절이 있고 컨테이너 재빌드·재시작, 키 갱신, 데이터 재적재, 사용자 실행 산출물 커밋 필요 여부가 점검되어 있는가(B-FP-052).
