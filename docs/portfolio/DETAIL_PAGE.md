## 30초 요약

공개 뷰티 광고의 영상 분석 결과와 제품·성분·효능 지식을 연결하고, 리서치·기획·평가 에이전트가 근거 소재를 참조하는 광고 기획안을 만든다. 근거 ID·분류 값·금지 표현은 코드로 검사하고, 사용자는 기획안 옆의 근거 카드·그래프를 읽고 승인·반려한다.

브랜드별 전용 데이터의 접근 범위를 코드로 제한했고, 사전 등록한 격리 실험에서 다른 테넌트 데이터 노출은 200건 요청 중 0이었다. 이는 로컬 검사 결과이며 운영 실적이나 실제 인증의 검증은 아니다. 출처: [P6 최종 결과 §2.4](../results/2026-11-20-p6-final.md#24-격리-observed_zero).

## 기술 스택

Python·uv, FastAPI(SSE), LangGraph, PostgreSQL, Neo4j, LiteLLM Python SDK, Next.js·React·TypeScript, Cytoscape, pytest·ruff·vitest를 사용한다. 출처 어댑터·모델 호출 래퍼·도메인 검사·저장소를 계층으로 나누고 아키텍처 테스트로 import 경계를 검사한다.

영상 분석은 Gemini, Supervisor·리서치와 기획은 OpenAI, 평가는 Anthropic이다. 시연은 sonnet 평가와 이미지 시안을 포함한다. Docker Compose와 로컬 API·웹이 촬영 환경이며 k3d 매니페스트는 로컬 배포 구성 검증용이다. [ADR-005·007·015](../ADR.md), [아키텍처](../ARCHITECTURE.md)를 따른다.

## 핵심 전략 3개

1. **제품 지식과 광고 관찰을 연결한다.** 제품·성분·효능·인증의 관계에 광고 소재의 관찰 라벨을 연결해 기획안의 효능 근거를 조회한다. 연결이 없으면 확인되지 않았다고 표시하고, 요청 효능을 정할 필요가 있으면 사용자의 선택을 받는다.
2. **검사 가능한 조건은 코드가 판정한다.** 근거 ID가 전달된 풀과 그래프에 존재하는지, 분류 값이 닫힌 목록에 속하는지, 금지 표현이 있는지 검사한다. 차별성과 요청 적합성은 별도 평가 모델이 채점한다. 위 되돌림 관측은 점수 향상 주장이 아니라 근거 ID 검사 실패를 고친 사례다.
3. **근거와 사용자 결정을 구조화한다.** 도구 출력에서 근거 카드·분포·그래프를 화면 명령으로 전달하고, 모델이 쓴 집계와 코드가 센 건수를 구분한다. 승인·반려 피드백과 대화는 작업 공간 범위로 저장한다.

## 아키텍처와 선택 이유

Supervisor는 과제 지시서를 리서치·기획·평가에 넘기고 구조화된 핸드오프를 받는다. 기획과 평가의 문맥·모델 공급사를 나눠 역할을 분리했다. PostgreSQL을 원본으로 두고 변경 시각을 기준으로 Neo4j에 MERGE하므로 그래프를 원본에서 재구성할 수 있다. 모델이 임의 Cypher를 작성하는 대신 닫힌 입력의 고수준 도구를 사용한다.

Neo4j는 제품·성분·효능·광고의 관계 탐색과 근거 그래프 표현을 위해 선택했다. Supervisor 구조와 온톨로지는 설계 전제이며 비교 실험의 판정과 구분한다. 저장소 간 동기화와 추가 모델 호출의 비용·지연이 대가다. 선택 근거와 한계는 [ADR-002·006·008·009·010·011·012](../ADR.md)에 기록했다.

기본 관측 기록은 로컬 JSONL이며 선택한 obs profile에 Langfuse 비동기 sink를 연결한다. 사후 기록의 시작·종료 시각과 원장 비용을 ingestion으로 전달하는 구현과 실제 화면 확인은 별도로 구분한다. [Langfuse 계약](../CONTRACTS.md#langfuse-2026-11-12-실측-임시-컨테이너-5개-끝난-뒤-볼륨까지-삭제)의 미확인 항목은 사용자 리허설로 확인한다.

## 데이터 파이프라인

공식 출처 어댑터가 소재·지표를 공통 형식으로 변환해 PostgreSQL에 저장한다. 콘텐츠 유형을 선별한 뒤 제품 소재를 영상 분석하고 닫힌 분류·스키마로 검증한다. 제품 정보는 공식몰, 성분 표준명·기능성 인증은 식약처 자료로 연결한다. 추출한 사실·원본 링크·수집 시각을 보존하며 수집 영상·이미지는 분석 후 삭제한다.

검증된 원본을 Neo4j에 증분 동기화하고, 요청 시 리서치 도구가 근거 풀과 패턴을 조회한다. 기획 → 코드 검사·모델 평가 → 필요 시 되돌림 → 기획안·참고용 이미지 시안·근거 화면 → 사용자 피드백으로 이어진다. 생성 시안은 수집 이미지와 별개이며 실제 제품 외형과 다를 수 있다.

## 부딪힌 문제와 해결 3건

### 도구가 찾은 제품을 모델이 보지 못했다

- **문제:** live-agent에서 인증 제품이 조회됐는데 최종 답은 해당 제품이 없다고 했다.
- **원인:** skeleton이 도구 결과의 요약만 모델 메시지에 넣어 실제 행과 근거 ID가 전달되지 않았다. 도구 자체의 조회 문제는 아니었다.
- **해결:** 상위 행·근거 ID를 모델 메시지로 만드는 공용 함수를 만들고 skeleton과 research가 함께 사용하도록 했다. 도구 결과를 데이터로 취급하는 지시도 함께 둔다.
- **결과:** 로그에는 수정 후 live 결과가 아직 보고되지 않았다고 기록돼 있다. 최종 답의 제품명 표시까지 확인됐다고 쓰지 않는다.
- **근거:** [문제 기록 — 그래프 조회는 정상인데 모델이 제품이 없다고 답했다](../TROUBLESHOOTING_LOG.md), `src/beautyads/agents/tool_messages.py`.

### 승인한 이미지 상한을 조립 코드가 낮췄다

- **문제:** 이미지 구성 요청이 HTTP 성공으로 끝났는데 시안은 생성되지 않았다.
- **원인:** 조립 코드가 설정값과 하드코딩 상한의 최솟값을 사용해 승인된 설정을 무시했다.
- **해결:** 설정을 상한의 단일 원본으로 사용하고 공급사·목적별 한도 사유와 설정 추종 검사를 추가했다.
- **결과:** 수정 뒤 개발 실행에서 이미지 생성 성공이 기록됐다. 이 관측을 현재 test 시연의 성공 보장으로 확대하지 않는다.
- **근거:** [문제 기록 — make live-agents: image 미생성](../TROUBLESHOOTING_LOG.md), [P5 결과 §1·§6](../results/2026-11-18-p5-live-agents.md#1-실행-개요).

### 중단된 재조회를 소재 부재로 기록했다

- **문제:** 시범 분석 대상이 `MEDIA_URL_MISSING`으로 끝났다.
- **원인:** Instagram 재조회가 앱 사용량 때문에 앞쪽 페이지에서 멈췄는데, 뒤쪽에서 찾지 못한 소재를 URL이 없다고 기록했다.
- **해결:** 스캔 중단을 `MEDIA_REFRESH_STOPPED`로 구분해 재시도 대상으로 남기고, 해당 작업만 다시 조회할 수 있도록 했다. 사용량과 중단 시점도 요약에 기록했다.
- **결과:** 시간을 두고 해당 작업을 재시도해 성공했다. 재조회가 끝나지 않은 상태와 URL이 실제로 없는 상태를 구분했다.
- **근거:** [문제 기록 — 재조회 스캔이 사용량으로 중단됐는데 URL 없음으로 확정됐다](../TROUBLESHOOTING_LOG.md), `src/beautyads/pipeline/media_flow.py`, `src/beautyads/eval/pilot_run.py`.

## 성과와 회고

측정으로 확인한 성과는 위 표의 테넌트 접근 제한 결과와 E1 기준을 넘은 축이다. 근거 ID 코드 검사가 실패한 시도를 되돌려 통과한 개발 관측도 남겼다. 이 결과는 광고 성과·현업 생산성·전체 기획 품질의 개선을 측정한 것이 아니다.

반대 결과와 미달 판정도 유지한다. P6의 E2는 `single_better`, E3은 `not_adopted`, E5는 `not_met:both`였다. 격리 판정 이름은 `observed_zero`다. 출처: [P6 최종 결과 §2](../results/2026-11-20-p6-final.md#2-사전-등록-판정). 요청 효능과 test 제품이 맞지 않는 요청이 섞였고, E3에는 도구 관측 창·URL 절단·조회 도구 부재 등 비교 구성의 한계가 있었다. 사후 진단은 사전 등록 판정을 바꾸지 않는다. 출처: [P6 §3.1·§3.2](../results/2026-11-20-p6-final.md#3-사후-진단).

E1의 hook_type·angle·talent·has_proof_segment·is_vertical·has_text_overlay·cta_type과 claims는 라벨 신뢰도가 낮아 결론의 근거로 쓰지 않는다. 사람 재검사 κ는 기억 효과를 포함한 라벨러의 내적 일관성이며 재현성 근거로 쓰지 않는다. 출처: [E1 §3.1·§6](../results/2026-11-19-e1-scoring.md#31-해석-단서-필수).

P6 실험 뒤 효능 선택·프롬프트가 변경됐으므로 당시 수치를 현재 시연 구성의 재측정 결과로 쓰지 않는다. 대화 압축·재작업 경로, 사람의 claim 일치 판정 등 미검증 범위도 남는다. 출처: [P6 §4·§5](../results/2026-11-20-p6-final.md#4-한계). 효능 근거 연결 확인은 부당 광고 여부의 법적 판정이 아니고, 현재 작업 공간 선택 헤더는 실제 인증이 아니다.
