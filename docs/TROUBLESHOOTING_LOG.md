# 문제·해결 기록

개발 중 실제로 부딪힌 문제를 그때그때 적는다. 포트폴리오의 "부딪힌 문제와 해결", "회고"는 여기서 고른다.

규칙:
- 실제로 일어난 일만 적는다. 일어날 것 같은 일, 남의 사례는 적지 않는다.
- 결과에는 확인한 값과 확인 방법을 적는다. 확인하지 못했으면 "미확인"이라고 적는다.
- 해결이 안 됐으면 안 된 채로 적는다.

형식: 날짜 / 문제 / 원인 / 해결 / 결과 / 근거

---

## 2026-11-11 브랜드 채널을 검색으로 찾았더니 엉뚱한 채널이 잡혔다
- **문제**: YouTube 검색으로 브랜드 채널을 찾자 8곳 중 3곳이 틀렸다(판매점 채널, 구독자 10명짜리 동명 채널, 해외 유통사 채널).
- **원인**: 채널 검색은 이름이 비슷한 채널을 돌려줄 뿐 공식 여부를 알려주지 않는다.
- **해결**: 브랜드 공식 사이트에 걸린 링크의 채널 ID와 대조해 목록을 고정했다(`config/sources.yaml`, 확인 방법을 계정마다 표기).
- **결과**: YouTube 17채널, Instagram 22계정 확정. Instagram은 추측한 계정 이름 2개가 존재하지 않았고 사이트 링크로 바로잡았다.
- **근거**: `config/sources.yaml`의 `verified` 값.

## 2026-11-11 같은 영상의 훅 유형이 호출마다 달랐다
- **문제**: 같은 영상이 한 번은 `question`, 한 번은 `problem`으로 분류됐다.
- **원인**: 훅 유형의 정의가 겹쳤다(질문 형식으로 고민을 제시하는 영상). 두 호출의 모델도 달랐다.
- **해결**: 값마다 관찰 가능한 판정 기준을 적고, 겹칠 때의 우선순위를 정했다(`docs/TAXONOMY.md`).
- **결과**: 미확인. 시범 라벨링과 E1에서 축별 일치도로 확인한다.

## 2026-11-12 제품 광고가 아닌 영상이 제품 소재처럼 분류됐다
- **문제**: 목욕탕 협업 팝업 홍보 릴스가 훅 `product_first`, 포맷 `ugc_style`로 분류됐다.
- **원인**: 공식 계정에는 제품 소재 외에 매장·행사 홍보와 브랜드 캠페인이 섞여 있는데, 분류에 "해당 없음"으로 빠질 길이 없었다.
- **해결**: 다른 축보다 먼저 판정하는 콘텐츠 유형 축을 추가하고 제품 소재만 분석하도록 했다.
- **결과**: 미확인. 콘텐츠 유형 선별의 재현율을 E1에서 잰다.

## 2026-11-11 영상 분석 호출이 과부하로 자주 실패했다
- **문제**: Gemini 호출에서 503 오류가 반복됐고, 한 번은 144초가 걸렸으며 한 번은 150초 넘게 응답이 없었다.
- **원인**: 미확인(서비스 쪽 과부하 메시지).
- **해결**: 검증 스크립트에서는 대기 후 재시도와 다른 모델로 넘기기를 넣어 통과시켰다. 파이프라인에는 소재별 작업 상태를 두고 실패한 건을 다음 실행에서 다시 집도록 설계했다.
- **결과**: 설계만 했고 구현 전이다. 실패율은 파이프라인의 운영 지표로 기록한다.

## 2026-11-12 성분으로 제품 라인 이름이 뽑혔다
- **문제**: 성분 항목에 "Hyalu-Cica"(제품 라인 이름)가 들어갔다. 화면의 실제 성분 표기는 Centella였다.
- **원인**: 열린 목록이라 모델이 성분처럼 보이는 단어를 그대로 넣었다.
- **해결**: 표준 성분 사전과 대조해 사전에 없는 값은 버리기로 했다.
- **결과**: 설계만 했고 구현 전이다.
