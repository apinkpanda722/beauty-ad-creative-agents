# PRD: beauty-ad-creative-agents

> 상태: 초안 (2026-11-12). 확정 전이며, 결정이 필요한 항목은 맨 아래 "미결 사항"에 모았다.

## 목표
뷰티 마케터가 신규 광고 소재를 기획할 때 경쟁 브랜드 소재 수십 개를 직접 보고 정리하는 일을, 에이전트가 **근거가 달린 기획안**으로 대신 만든다.

**주 서사:** 흩어진 영상 소재를 지식그래프로 구조화하고, 역할이 나뉜 에이전트들이 그 그래프를 근거로 기획안을 만들고 스스로 검증한다. **보조 서사:** 멀티에이전트와 온톨로지를 쓴 이유를 단일 에이전트·벡터 검색과의 비교 수치로 보인다.

## 사용자
- 뷰티 브랜드의 콘텐츠·퍼포먼스 마케터 1인. 사내 데이터 없이 공개 소재만으로 경쟁 분석과 기획 초안을 얻으려는 사람.
- 테넌트는 한 회사 안의 브랜드별 작업 공간이다. 여러 브랜드를 가진 회사가 공통 기반을 함께 쓰고 브랜드마다 작업 공간을 나눈다. 브랜드가 하나인 회사는 작업 공간 하나로 쓴다. 공개 소재 분석은 공용이고, 브랜드 프로필·기획안·피드백·대화 이력은 테넌트 전용이다. 데모 작업 공간은 2개다.
- 데모는 로컬에서 실행하며, 실제 인증 대신 데모 테넌트를 고르는 화면을 둔다.

## 핵심 시나리오
| 유형 | 요청 예 | 결과 |
|---|---|---|
| S1 패턴 질의 | "조회수 상위 선케어 릴스가 공통으로 쓰는 훅은?" | 패턴 요약 + 근거 소재 링크 |
| S2 관계 질의 | "마스크팩에서 많이 쓰는 훅이 세럼에서도 쓰이나?" | 카테고리 간 비교 + 근거 소재 |
| S3 기획 요청 | "진정 소구 세럼 신규 릴스 3안 기획해줘" | 기획안 3개(훅·장면 구성·카피·이미지 시안) + 평가 점수 + 근거 |
| S4 피드백 | 기획안 승인·반려와 사유 입력 | 그래프에 저장, 다음 기획에 반영 |
| S5 경계 | 범위 밖 카테고리, 근거 소재가 없는 조건 | 근거 없음을 밝히고 지어내지 않음 |
| S6 테넌트 격리 | 다른 브랜드의 피드백·기획안·금지 표현을 물어보거나 끌어내려는 요청 | 자기 테넌트 범위만 답함. 다른 테넌트 데이터 노출 0 |

대상 목록은 `config/sources.yaml`에 있다.

제품 상세페이지 수집 원칙:
- 브랜드 공식몰만 대상으로 한다. 판매처(올리브영 등)는 쓰지 않는다. 사용 가능 12곳, 제외 2곳(`docs/CONTRACTS.md`). 대표 단품 후보는 `config/product_candidates.yaml`(임시, M1에서 광고 등장 빈도로 확정).
- robots.txt를 지킨다. AI 크롤러를 명시해 막은 사이트는 제외한다(2026-11-12 확인: 토리든이 ClaudeBot·GPTBot을 막아 제외).
- 대표 제품만, 요청 간격을 두고 받는다. 비영리 포트폴리오 용도다.
- 이미지는 추출 중에만 두고 지운다. 저장하는 것은 추출한 사실(전성분, 효능 표기, 권장 피부 타입, 제형, 가격)과 원본 페이지 주소, 수집 시각뿐이다. 이미지를 저장소나 화면에 다시 싣지 않는다.

확인된 제약:
- YouTube는 영상 파일을 주지 않는다. Gemini의 YouTube 주소 입력(프리뷰 기능, 무료 범위 하루 8시간 분량, 공개 영상만)으로 분석한다. 구간 지정(`start_offset`·`end_offset`·`fps`)이 YouTube 주소에도 동작함을 확인했다.
- Instagram 릴스의 영상 주소는 표본 195건 중 101건(52%)만 반환됐다. 주소가 없는 릴스는 캡션·지표만 그래프에 넣고 영상 분석 대상에서 뺀다. 주소가 있는 릴스는 파일(1~4MB)을 받아 Gemini Files API에 올려 분석하는 경로를 2건으로 확인했다(2026-11-12).
- 영상 파일은 분석이 끝나면 지우고, 추출 결과와 원본 링크만 남긴다. Gemini에 올린 파일은 약 48시간 뒤 만료되며 분석 직후 삭제를 요청한다.
- 공식 계정에는 제품 소재가 아닌 콘텐츠(매장·행사 홍보, 브랜드 캠페인)가 섞여 있다. 분류 전에 콘텐츠 유형을 먼저 가른다(`docs/TAXONOMY.md`의 0번 축).
- 모델 출력은 번역하지 않고 원문 그대로 저장한다.
- YouTube·Instagram의 성과 지표는 조회수·좋아요·댓글 수다. 광고비로 올린 조회와 자연 조회를 구분할 수 없다.
- TikTok은 집행된 광고만 나오고, 지표는 게재 시작일·종료일과 도달 사용자 수 구간(`"600K-700K"`)이다. 영상 파일을 직접 받을 수 있다(4~10MB). EU 게재분만 조회되므로 소재 언어는 주로 영어·유럽 언어다.
- TikTok은 브랜드 이름으로 검색하면 브랜드가 직접 집행한 광고와 판매처(세포라 등)·개인이 집행한 광고가 섞인다. 광고주 이름의 40%가 숫자로 와서 이름만으로는 집행 주체를 가를 수 없다. 소재마다 집행 주체(브랜드 직접, 판매처, 개인, 불명)를 둔다.
- Gemini 호출은 검증 중 과부하 오류(503)와 150초 넘는 지연이 잦았다. 재시도와 대기가 필수다.

## 핵심 기능
1. **수집 파이프라인 (에이전트 아님):** 대상 계정의 소재와 지표를 주기적으로 가져와 중복을 제거한다. 판단이 없는 정해진 작업이라 스케줄 파이프라인으로 둔다.
2. **소재 분석 에이전트 (오프라인):** 영상·캡션을 보고 `docs/TAXONOMY.md`의 닫힌 분류로 라벨을 추출한다. 훅은 첫 3초 구간만 따로 본다. 출력은 스키마 검증을 통과해야 그래프에 들어간다.
3. **온톨로지(지식그래프), 두 층:** 1층은 제품 지식(제품, 성분과 별칭, 효능, 피부 고민·타입, 제형, 기능성 인증, 표현 규칙), 2층은 광고 관찰(소재, 훅·앵글·포맷 등 분류, 피드백)이고 2층은 1층에 연결된다(소재가 제품을 홍보하고 효능을 주장한다). 노드와 관계는 역량 질문(`docs/COMPETENCY_QUESTIONS.md`)으로 정하고, 모든 역량 질문이 1~4홉으로 답해지면 완성으로 본다. 수집 기록은 그래프가 아니라 PostgreSQL에 둔다(`docs/ARCHITECTURE.md`의 온톨로지).
4. **Supervisor:** 요청을 해석해 하위 에이전트를 부르고 종료를 판단한다. 단계 수와 비용 상한을 코드로 강제한다.
5. **리서치 에이전트:** 그래프 탐색 도구로 조건에 맞는 패턴과 근거 소재를 찾는다. 쿼리를 직접 쓰게 하지 않고 고수준 도구를 준다.
6. **기획 에이전트:** 리서치 결과를 근거로 기획안과 이미지 시안을 만든다. 기획안의 모든 주장에 근거 소재 ID를 단다.
7. **평가 에이전트:** 기획안을 채점하고 기준 미달이면 기획으로 되돌린다(최대 2회). 인용한 소재·패턴이 그래프에 실제로 있는지, 금지 표현이 있는지는 **코드가** 판정하고, LLM은 차별성과 요청 적합성만 채점한다. 기획과 다른 회사 모델을 쓴다.
8. **피드백 메모리:** 승인·반려와 사유를 그래프에 저장하고 다음 기획의 입력으로 넣는다.
9. **관측:** 요청 하나를 trace 하나로 남긴다(Langfuse). 에이전트별 호출 수·비용·지연을 본다.
10. **컨텍스트 관리:** Supervisor는 하위 에이전트에 대화 전체가 아니라 과제 지시서를 넘기고, 하위 에이전트는 구조화된 요약(결론, 근거 ID 목록, 집계 값)으로 돌려준다. 원자료는 상태 저장소에 두고 ID로 참조한다. 여러 턴이 쌓이면 대화 이력을 압축하되 근거 ID·조건·피드백은 보존한다. 에이전트별 입력 토큰 상한을 둔다(`docs/ARCHITECTURE.md`의 컨텍스트 관리).
11. **멀티테넌트 격리:** 테넌트는 세션이 정하고 도구 입력에는 테넌트 칸이 없다. 모든 도구가 호출 전에 실행 컨텍스트의 `tenant_id`로 범위를 건다. 전용 데이터, 체크포인터, 압축 요약, trace가 모두 테넌트 단위다. 검사 실패 시 요청을 거부한다(`docs/ARCHITECTURE.md`의 멀티테넌트).
12. **원본에서 그래프로 증분 동기화:** PostgreSQL을 원본으로 두고 바뀐 행만 Neo4j에 반영한다. 반복 실행해도 결과가 같고, 그래프를 처음부터 다시 만들 수 있다.
13. **도구 설계 규칙:** 그래프 도구를 조회·집계·비교·표시로 나누고, 도구 설명에 언제 쓰고 언제 쓰지 않는지를 적는다. 실패는 구조화된 실패로 돌려준다.
14. **화면 명령:** 도구가 근거 카드·그래프 조각·분포 차트·기획안 카드를 그리라는 명령을 답변 글자와 별도 이벤트로 보낸다.
15. **요청 공통 장치:** 기준일 고정(상대 날짜는 서버가 푼다), 작업 공간별 동적 프롬프트, 한도, 오류 처리, 대화 상태 보존 기간.
16. **웹 화면:** 아래 "시연과 포트폴리오 산출물" 참고.

## 시연과 포트폴리오 산출물
프로젝트 상세 페이지에 그대로 실을 수 있는 자료를 처음부터 제품 요구사항으로 둔다.

| 산출물 | 요구사항 |
|---|---|
| 대화 화면 | 요청 입력, 응답 스트리밍(SSE), 에이전트 단계 진행 표시(Supervisor → 리서치 → 기획 → 평가) |
| 근거 카드 | 기획안 옆에 근거 소재 썸네일·링크·지표를 카드로 표시 |
| 온톨로지 그래프 화면 | 응답에 쓰인 노드와 관계를 그래프로 그려 준다. 전체 스키마 보기도 제공 |
| 시연 영상 | 30초 이내, 요청 하나가 끝까지 처리되는 장면. 페이지에는 자동 재생되는 짧은 영상(GIF처럼)으로 넣는다 |
| 화면 캡처 | 대화 화면, 그래프 화면, trace 화면 각 1장. 재가공 없이 원본 그대로 싣는다 |
| 수치 표 | 값마다 기준일과 측정 조건을 한 줄로 병기하고, 측정값·관측값·설계 추정 중 무엇인지 표시한다. 모든 수치는 `docs/results/`의 결과 문서에서만 가져온다(도구 수는 코드의 등록 목록에서) |
| 로컬 실행 절차 | 저장소를 받아 명령 한 줄로 전체를 띄울 수 있다(README에 절차). 로컬 Kubernetes(k3d) 매니페스트 포함 |

개발 중 실제로 부딪힌 문제는 `docs/TROUBLESHOOTING_LOG.md`에 그때그때 적는다(문제, 원인, 해결, 결과, 근거). 상세 페이지의 "부딪힌 문제와 해결"과 "회고"는 이 기록에서 고르고, 실제로 일어나지 않은 일은 쓰지 않는다.

상세 페이지 구성은 30초 요약 → 수치 → 기술 스택 → 시연 영상·그래프 화면 → 배경(이전·이후) → 핵심 전략 3개 → 아키텍처와 선택 이유 → 데이터 파이프라인 → 부딪힌 문제와 해결 3건 → 성과와 회고 순서를 따른다.

## 검증 실험
가설과 판정 기준은 결과를 보기 전에 `docs/EVAL.md`에 등록한다.

| 실험 | 방법 | 보이려는 것 |
|---|---|---|
| E1 분석 정확도 | 지원 3종 제품 소재 전수(목표 50건, 실제 48건, 2026-11-13 사전 등록 정정)의 모델 라벨과 사람 라벨 일치도(축별), 7일 간격 재라벨 일치도 | 멀티모달 분석을 믿을 수 있는가 |
| E2 단일 대 Supervisor | 같은 요청 20개를 두 구성으로 실행. 품질 점수·비용·지연 | 멀티에이전트를 택한 근거 |
| E3 그래프 대 벡터 검색 | 관계형 질문 세트의 정답률 | 온톨로지가 필요한 근거 |
| E4 평가 점수 타당성 | 조회수 상위 소재와 하위 소재를 평가 에이전트가 구분하는지 | 평가 에이전트가 의미 있는가 |
| E5 컨텍스트 관리 효과 | 구조화 핸드오프를 켠 구성과 원자료를 그대로 넘기는 구성 비교. 입력 토큰·비용·근거 유효율 | 컨텍스트 설계가 비용을 줄이면서 근거를 잃지 않는가 |

E2 결과와 무관하게 Supervisor 구성을 유지한다. 품질 차이를 확인하지 못하면 늘어난 비용·지연을 대가로 그대로 보고한다. 판정 기준은 `docs/EVAL.md`에 동결했다.

## 범위 밖
- 유료 서버 상시 배포
- 영상 생성(Image-to-Video, Text-to-Video)
- 광고 집행·예산 최적화, 광고 계정 연동
- 실제 인증(IdP 연동), 테넌트 안의 사용자별 권한, 과금 — 데모 테넌트 선택과 테넌트 단위 격리까지만 한다
- 범위 밖 카테고리(마스크팩·세럼/앰플·선케어 외) 분석
- 약관에 어긋나는 수집(크롤링, 영상 무단 다운로드)
- 대기업 계열 브랜드(라네즈·이니스프리) — 건수가 쏠려 1차에서 제외
- 현업 마케터 검수 — 1인 라벨링과 재검사 일치도로 대신한다

## 성공 기준
- S1~S5 시나리오가 로컬 환경에서 끝까지 동작한다.
- 기획안의 근거 소재 ID가 100% 그래프에 실제로 존재한다(코드 검사).
- 테넌트 격리 검사에서 다른 테넌트 데이터 노출이 0건이다(`docs/EVAL.md`의 격리 검사).
- 카테고리 3개 각각 분석 완료 소재 100건 이상.
- E1~E4 결과가 사전 등록한 기준과 함께 문서로 남는다(기준 미달도 그대로 보고).
- 시연 영상, 화면 캡처 3장, 수치 표가 준비된다.

## 마일스톤 (하네스 phase = PR 1개)
기간은 3주(2026-11-12 ~ 2026-12-02)다.

| M | 산출물 | 측정 |
|---|---|---|
| M0 | 설계 문서(ARCHITECTURE·ADR·EVAL), compose(Neo4j·Postgres·Langfuse), `make verify` 구성 | — |
| M1 | 역량 질문 동결, 1층 제품 지식 구축(대표 제품·성분·효능), 수집 어댑터 3개(YouTube·Instagram·TikTok), 공통 소재 형식, 분류 v1 동결, 소재 분석 에이전트, 그래프 적재 | 출처·카테고리별 분석 건수, 호출 실패율, 역량 질문 1~4홉 충족 여부 |
| M2 | 그래프 도구, 리서치·기획·평가 에이전트, Supervisor, 피드백 메모리, 평가셋 | E1~E4 |
| M3 | 웹 화면(대화·근거 카드·그래프), 로컬 실행 절차와 k3d 매니페스트, 시연 영상, 상세 페이지 원고 | 성공 기준 점검 |

## 확정 사항 (2026-11-12, 상세는 `docs/ADR.md`)
- 모델: 영상 분석 `gemini-3.6-flash`, Supervisor·리서치 `gpt-6-luna`, 기획 `gpt-6.1-terra`, 평가 `claude-sonnet-5-5`. 개발 반복은 `gpt-6-luna`와 `claude-haiku-5-5`. 시스템 프롬프트·도구 정의 캐시.
- 그래프 DB: Neo4j.
- 실행 환경: 로컬. 유료 서버에 상시 배포하지 않는다. Kubernetes 매니페스트는 로컬 클러스터(k3d)용으로 만든다.
- 월 비용 상한: 약 5만 원(모델 호출만). 확정 계획의 견적은 약 2.7만 원.

## 미결 사항
1. (해결) 모델 조합과 실행 계획 확정, 프로젝트 전체 견적 약 $18.6(약 2.7만 원, `docs/COST_ESTIMATE.md`). 분석 비용은 M1 첫 분석 시범 직후, 온라인 요청 비용은 M2 첫 실측 뒤 재계산.
1-1. (해결) 브랜드 공식몰 이용약관: 확인한 12곳 모두 영리 목적 복제·배포만 금지하고 크롤링 금지 조항은 없다(2026-11-12).
1-2-1. (해결) 식약처 「화장품 표시·광고 관리 지침」 첨부 PDF 정독(2026-11-12, `docs/ADR.md` ADR-014).
1-2. 성분과 효능 연결의 근거 자료. 공공 데이터에 효능 정보가 있는지 확인 전이다.
1-3. (해결) 화장품 표시·광고 규정 원문 확인: 1-2-1과 같다. 안내서는 법적 효력이 없어 "참고"로 쓴다(ADR-014).
2. (해결) Langfuse: 로컬 셀프호스팅을 compose 선택 profile `obs`로 둔다. Cloud는 쓰지 않는다(ADR-016).
3. 무료 호스팅에 올리는 읽기 전용 재생 데모(저장한 실행 결과를 보여주는 정적 페이지)를 M3에 넣을지.
4. 이미지 시안 생성에 쓸 모델과 건당 비용 상한.
5. 평가셋 요청 20개와 관계형 질문 세트를 누가 어떻게 만들지(1인 작성의 편향 처리).
6. 인스타그램 넘버즈인 계정 2개는 프로필 문구로만 공식 판단했다. 포함 여부.
