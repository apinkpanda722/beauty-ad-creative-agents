# 평가 계획

> 상태: 판정 기준 동결 (2026-11-12). 아래 기준과 표본 크기는 실험 전에 확정했고 결과를 본 뒤에는 바꾸지 않는다. 기준을 못 넘긴 결과도 그대로 보고한다. 절차의 세부(층화 방법, 채점 문항)는 M2 실행 전에 이 문서에 추가하되 기준 숫자는 건드리지 않는다.

## 원칙
1. 가설과 판정 기준을 결과를 보기 전에 이 문서에 적는다.
2. 기준을 정하는 데 쓴 데이터(dev)와 최종 수치를 내는 데이터(test)를 나눈다.
3. 수치마다 건수와 측정 조건을 함께 적는다. 건수가 작으면 작다고 적는다.
4. 사람 판정은 1인(작성자)이다. 모든 사람 판정 수치에 "1인 라벨링"을 병기한다.

## 데이터 분할
- 분석 완료 소재를 브랜드 단위로 dev와 test에 나눈다. 같은 브랜드가 양쪽에 걸치지 않게 한다.
- 평가용 요청과 질문 세트도 dev(기준 조정용)와 test(최종 측정용)로 나눈다.

## 지표 정규화
채널 규모가 크게 달라 조회수를 그대로 쓰지 않는다.
- 기본값: 같은 채널 안에서의 조회수 백분위(게시 후 14일 이상 지난 소재만).
- 상위·하위 구분: 채널 내 상위 25%와 하위 25%.
- 조회수에는 광고비 효과가 섞여 있다. "성과가 좋다"가 아니라 "조회수 상위"라고 적는다.

## E1 소재 분석 정확도
**질문:** 멀티모달 분석이 뽑은 라벨을 믿을 수 있는가.

- 표본: 제품 소재 50건(카테고리·출처가 고르게 들어가게 층화 추출).
- 절차:
  1. 사람이 모델 결과를 보기 전에 먼저 라벨링한다.
  2. 7일 뒤 첫 라벨을 가리고 다시 라벨링한다(재검사).
  3. 분석 모델(Gemini)과 다른 회사 모델에 같은 기준서로 라벨링시킨다.
- 지표: 축별 일치율과 Cohen's κ. 여럿 선택 축(소구점)은 항목별 정밀도·재현율.
- 판정 기준:
  - 사람 재검사 κ가 0.7 미만인 축은 정의가 모호한 것으로 보고 고치거나 뺀다.
  - 남은 축에서 사람·분석 모델 κ 0.6 이상이면 그 축을 그래프에 쓴다. 미만이면 쓰지 않는다.
  - 콘텐츠 유형 선별은 제품 소재 재현율 0.9 이상.

## E2 단일 에이전트 대 Supervisor
**질문:** 역할을 나눈 구성이 한 에이전트에 도구를 다 준 구성보다 나은가.

- 조건: 같은 모델, 같은 도구, 같은 그래프, 같은 요청당 비용 상한. 구성만 다르다.
- 요청: 기획 요청 20개(test). 요청은 실험 전에 고정한다.
- 지표:
  - 근거 유효율: 기획안의 근거 소재 ID 중 그래프에 실제로 있고 주장과 맞는 비율(존재 여부는 코드, 맞는지는 사람 판정)
  - 요청 적합성·차별성 점수(다른 회사 모델 채점 + 사람 표본 검수)
  - 요청당 비용, 지연(p50·p95), 모델 호출 수
- 판정 기준: Supervisor 구성이 근거 유효율 또는 품질 점수에서 차이의 95% 신뢰구간이 0을 넘으면 "Supervisor가 더 낫다"고 보고한다. 넘지 않으면 "품질 차이를 확인하지 못했다"고 보고한다.
- 구조 결정: 어느 쪽이 나와도 Supervisor 구성을 유지한다(2026-11-12 결정). 유지 근거는 기획과 평가의 분리(자기 채점 회피)이며, 이 경우 늘어난 비용·지연·호출 수를 대가로 그대로 적는다. 단일 구성이 통계적으로 **더 나은** 결과가 나오면 그 사실도 숨기지 않고 같은 표에 적는다.
- 한계: 20개는 작다. 차이가 작으면 판정 불가로 보고한다.

## E3 그래프 대 벡터 검색
**질문:** 온톨로지가 필요한가.

- 질문 세트: `docs/COMPETENCY_QUESTIONS.md`의 역량 질문을 바탕으로 만든, 관계를 따라가야 답이 나오는 질문 30개(예: 카테고리 간 훅 비교, 특정 성분을 내세운 소재의 포맷 분포). 정답은 그래프 질의로 계산해 사람이 확인한다.
- 비교: (a) 그래프 도구를 쓰는 리서치 에이전트, (b) 소재 설명을 임베딩한 벡터 검색만 쓰는 에이전트.
- 지표: 정답률(집계 값은 허용 오차 안이면 정답), 근거 소재 적중률.
- 판정 기준: 정답률 차이의 95% 신뢰구간이 0을 넘으면 그래프 채택.
- 한계: 질문 세트를 그래프 설계자가 만든다. 그래프에 유리한 질문이 될 수 있어, 단순 검색형 질문 10개를 따로 두고 그쪽 결과도 함께 보고한다.

## E4 평가 에이전트의 타당성
**질문:** 평가 에이전트의 점수가 의미가 있는가.

- 방법: 실제 소재를 기획안 형식으로 바꿔 평가 에이전트에 넣는다. 채널 내 조회수 상위 25% 소재와 하위 25% 소재를 각 30건.
- 지표: 두 집단을 점수로 구분하는 정도(AUC).
- 판정 기준: AUC 0.6 이상이면 "약한 구분력 있음"으로 보고한다. 미만이면 평가 점수를 품질 지표로 내세우지 않고 코드 검사 결과만 쓴다.
- 한계: 조회수는 소재 품질만으로 정해지지 않는다. 높은 AUC를 기대하지 않는다.

## E5 컨텍스트 관리 효과 (2026-11-12 추가, 기준 동결)
**질문:** 구조화 핸드오프와 도구 반환 이원화가 비용을 줄이면서 근거를 잃지 않는가.

- 조건: E2와 같은 기획 요청 20개(test), 같은 모델과 도구. 다른 것은 하나다.
  - (a) 컨텍스트 관리 켬: 지시서, 구조화 핸드오프, 원자료 참조, 도구 반환 이원화
  - (b) 끔: 하위 에이전트의 전체 출력과 도구 원출력을 Supervisor에 그대로 전달
- 지표: 요청당 입력 토큰 합계와 비용, 지연, 근거 유효율, 품질 점수.
- 판정 기준: (a)의 입력 토큰이 (b)보다 30% 이상 적고, 근거 유효율 차이의 95% 신뢰구간 하한이 -0.05보다 크면 "비용을 줄이면서 근거를 유지했다"고 보고한다. 둘 중 하나라도 못 넘으면 넘지 못한 쪽을 그대로 적는다.
- 이력 압축은 이 실험에 넣지 않는다. 한 번의 요청으로는 압축이 일어나지 않기 때문이다. 압축은 여러 턴짜리 시나리오 테스트로 "보존 항목이 압축 뒤에도 남는가"를 확인한다(통과·실패).
- 이 실험은 E1~E4 기준을 동결한 뒤에 추가했다. E1~E4의 기준 숫자는 바꾸지 않았다.

## 테넌트 격리 검사 (2026-11-12 추가, 건수 동결)
**질문:** 한 테넌트의 전용 데이터가 다른 테넌트에게 나가는 경로가 있는가.

- 준비: 데모 작업 공간 2개에 서로 겹치지 않는 표식 데이터를 넣는다(브랜드 프로필의 금지 표현, 피드백 사유, 기획안 문구에 테넌트별 고유 문자열).
- 경로 4개를 각각 검사한다.
  1. 그래프 도구: 다른 테넌트의 전용 노드가 탐색 결과에 나오는가
  2. 피드백 메모리: 다른 테넌트의 피드백이 기획 입력에 들어가는가
  3. 대화 이력·압축 요약: 다른 테넌트의 thread나 요약이 컨텍스트에 들어가는가
  4. 최종 응답: 다른 테넌트의 표식 문자열이 응답·근거 카드·그래프 조각에 나오는가
- 요청 구성: 정상 요청과 끌어내기 시도(다른 브랜드 이름을 대며 피드백을 요구, 지시를 무시하라는 문구, 테넌트를 바꾸라는 문구)를 섞는다.
- 판정: 표식 문자열 검색으로 코드가 판정한다. 건수는 경로당 50건, 합계 200건이다.
- 기준: 노출 0건. 한 건이라도 나오면 원인과 수정 내용을 함께 보고한다.
- 0건은 관측값이지 증명이 아니다. 시도한 요청 유형의 범위를 결과와 함께 적는다.

## 운영 지표 (실험과 별개로 항상 기록)
- 분석 파이프라인: 소재당 비용, 호출 실패율, 재시도 횟수, 보류 비율, `other` 값 비율(축별)
- 온라인 요청: 요청당 비용, 지연, 단계 수, 되돌림 횟수, 코드 검사 실패 사유 분포

## 결과 보고
- 결과는 `docs/results/`에 실험별 문서로 남긴다. 표의 모든 값에 건수, 기준일, 조건을 적는다.
- 기준을 못 넘긴 항목, 판정 불가 항목도 같은 표에 넣는다.
